# Relay schema extraction research

Research performed against the official Relay v21.0.1 package and compiler source on 2026-09-19.

## Findings

The published `relay-compiler@21.0.1` package contains a platform binary, a small Node launcher, the compiler configuration JSON Schema, and `relay-extensions.graphql`. Its package entry point resolves the binary; it does not export a JavaScript schema builder or a schema-to-SDL API. The package contents and entry point are visible in the [official npm package metadata](https://registry.npmjs.org/relay-compiler/21.0.1) and the [Relay compiler package source](https://github.com/facebook/relay/tree/v21.0.1/packages/relay-compiler).

Relay's native schema pipeline is implemented inside the Rust compiler. The official [build_schema.rs](https://github.com/facebook/relay/blob/v21.0.1/compiler/crates/relay-compiler/src/build_project/build_schema.rs) parses the configured server schema, reads `schemaExtensions`, converts resolver docblock IR into schema documents, extends resolver fields, and validates the resulting composite schema. The resolver conversion is implemented by [ir_to_schema.rs](https://github.com/facebook/relay/blob/v21.0.1/compiler/crates/relay-compiler/src/build_project/build_resolvers_schema/ir_to_schema.rs), and resolver docblocks are parsed by [extract_docblock_ir.rs](https://github.com/facebook/relay/blob/v21.0.1/compiler/crates/relay-compiler/src/build_project/build_resolvers_schema/extract_docblock_ir.rs). This establishes the required composition order: server SDL, client schema extensions, resolver types, then resolver fields.

Relay's binary has an LSP mode (`relay lsp`) and exposes native custom requests. The official [LSP dispatcher](https://github.com/facebook/relay/blob/v21.0.1/compiler/crates/relay-lsp/src/server.rs) registers `relay/searchSchemaItems` and `relay/exploreSchemaForType`. The [search request](https://github.com/facebook/relay/blob/v21.0.1/compiler/crates/relay-lsp/src/search_schema_items.rs) enumerates all native schema types with pagination. The [explore request](https://github.com/facebook/relay/blob/v21.0.1/compiler/crates/relay-lsp/src/explore_schema_for_type.rs) returns a type's fields, argument types/defaults, interfaces, union members, enum values, applied directives, and extension status. The response model is defined in [types.rs](https://github.com/facebook/relay/blob/v21.0.1/compiler/crates/relay-lsp/src/explore_schema_for_type/types.rs). These requests are useful for interactive exploration; the implementation uses the Rust schema builder for complete export, as described below.

The official [compiler configuration guide](https://relay.dev/docs/getting-started/compiler/) documents config discovery from `relay.config.json`, `relay.config.js/mjs/ts`, or a `relay` key in `package.json`. The published [config schema](https://unpkg.com/relay-compiler@21.0.1/relay-compiler-config-schema.json) defines single-project `schema`/`schemaExtensions` and multi-project `projects`/`sources`; a multi-project project may use `schema`, `schemaDir`, or `schemaCompact`. Compact schemas are compiler-internal binary data and have no documented SDL export.

## Implementation decision

The schema package uses a Rust helper pinned to Relay v21.0.1. Relay publicly exports `FileSource`, `GraphQLAsts`, and `build_schema` from its [compiler crate](https://github.com/facebook/relay/blob/v21.0.1/compiler/crates/relay-compiler/src/lib.rs). The helper loads sources with `FileSourceKind::WalkDir`, parses their GraphQL documents, builds the selected project's schema, and prints it with [`schema_print::print`](https://github.com/facebook/relay/blob/v21.0.1/compiler/crates/schema-print/src/print_schema.rs). It does not run operation transforms, artifact generation, or persistence.

The LSP explorer cannot provide a complete export: [object fields are capped at 100](https://github.com/facebook/relay/blob/v21.0.1/compiler/crates/relay-lsp/src/explore_schema_for_type/types.rs), and some schema metadata is omitted. The kitchen-sink fixture verifies that the native helper returns all 120 fields of a wide object. There is no regex or LSP fallback in the implementation.

The native [schema printer](https://github.com/facebook/relay/blob/v21.0.1/compiler/crates/schema-print/src/printer.rs) retains field types, arguments/defaults, and applied directives, including deprecations and resolver import paths. It omits documentation descriptions, and [schema construction](https://github.com/facebook/relay/blob/v21.0.1/compiler/crates/schema/src/in_memory.rs) also drops some type and argument descriptions. The helper therefore collects description metadata from the native schema and the selected project's compiler-loaded schema and resolver inputs. The wrapper attaches that metadata to the compiler-generated SDL's GraphQL AST before printing and building the inspection schema. This preserves descriptions without losing applied directives. Serialization preserves multiline and escaped text, including empty descriptions. Original formatting and ordinary `#` comments are not retained.

GraphQL.js builds the inspection schema with validation assumptions because Relay includes reserved internal fields. Document validation remains standard GraphQL validation, not Relay operation validation.

The wrapper supports JSON configuration and `package.json`'s `relay` key. It checks a target project's installed compiler version against the helper version, and rejects mismatches. The current build is tied to Relay 21.0.1 and requires Rust during source builds; native executables are packaged for the machine running the build.
